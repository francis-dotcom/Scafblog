Why existing tools don't solve this
Tools like Datadog, Sentry, and even LLM-specific platforms like Langfuse and Helicone were designed around a simple mental model: one request, one response, done.
That model works fine for:
A single chatbot response
It breaks completely for agents, because agents are:
Stateful — each step depends on the output of the previous one. A hallucination in step 2 is invisible by step 5.
Multi-model — different steps may call different models with different reliability profiles.
Non-deterministic — the same input doesn't produce the same output twice. You can't just replay a test.
Cost-compounding — a loop that hits an edge case can make 50 LLM calls before returning. At GPT-4o pricing, that's a surprise invoice.
Contradiction-prone — a model can state X in step 3 and contradict X in step 8. Neither step looks wrong individually.
The result: teams are running agents with zero visibility into what's actually happening between the first request and the final output.

Agent circuit breaker
Runaway agent loops are expensive and hard to detect manually. Ajah solves this at the infrastructure level.

Narrative drift detection
This is the failure mode that's hardest to catch manually.

Dead step detection
If an agent is looping — producing the same output it produced two steps ago — you want to know before it makes 15 more identical calls.
Ajah compares each response against the prior steps in the session using trigram similarity. If overlap exceeds 85%, the step is flagged as a dead step.

### The Silent Failures of AI Agents

The advent of large language models (LLMs) has revolutionized the deployment of AI agents across various applications. However, as these systems become increasingly complex, the risk of silent failures—where the agent operates under the false assumption of success—has escalated. A notable case involved a customer support agent that processed refund requests. Despite returning HTTP 200 status codes at every step, the agent ultimately denied a valid refund due to a hallucinated policy. This incident highlights a critical observability gap: the inability to detect deviations from expected behavior in multi-step workflows, leading to significant operational risks.

### The Complexity of Multi-Step Processes

Multi-step AI agents introduce layers of complexity that single-step systems do not encounter. Each step is contingent upon the output of the previous one, creating a dependency chain that can amplify errors. For instance, if an agent misinterprets a return policy, subsequent actions—like refund processing—are based on flawed data. This stateful nature makes it challenging to identify errors in real-time, as a hallucination in an early step can remain undetected until it results in a user-facing failure. Consequently, robust observability mechanisms are essential to track and analyze each step, enabling developers to identify and rectify issues proactively.

### Limitations of Current Observability Tools

Existing observability tools, such as Datadog, Sentry, Langfuse, and Helicone, are primarily designed for straightforward request-response models. They excel in scenarios where interactions are isolated and deterministic but struggle in the context of multi-step LLM systems. These tools typically log errors but fail to provide insights into how prior outputs influence subsequent actions. For example, while they may indicate that an error occurred, they do not elucidate how a hallucinated output in an earlier step led to that error. This lack of visibility leaves developers unaware of potential failures until they escalate into significant issues.

### Key Features for Effective Observability

To bridge the observability gap, effective solutions must incorporate several key features. Hallucination scoring is vital, assessing the risk of hallucination at each step, which helps developers pinpoint where inaccuracies may arise. Session visualization tools can represent the entire workflow as a tree, displaying quality scores for each step, thus facilitating quick identification of problematic areas. Additionally, dead step detection can identify loops or redundant outputs, allowing developers to mitigate costly and unproductive behaviors. Together, these features create a comprehensive framework for monitoring the reliability of AI agents.

### Introducing Ajah: A Novel Observability Gateway

To address the challenges associated with observability in multi-step AI systems, we developed Ajah, an open-source LLM observability gateway. Ajah serves as an intermediary between the application and the LLM provider, enhancing visibility with minimal code changes. It automatically scores each response for hallucination risk and provides detailed insights into session performance. For instance, if a customer support agent processes a refund based on a hallucinated policy, Ajah will flag that specific step, allowing developers to trace the error back to its source. This proactive approach can significantly reduce the likelihood of silent failures.

### Integrating Ajah into Existing Systems

Integrating Ajah into your existing infrastructure is designed to be straightforward and minimally invasive. Developers can clone the repository and run the gateway with minimal setup. The installation process involves integrating the Ajah SDK into existing agents, enabling them to leverage observability features without substantial overhead. Below is a sample integration:

### Financial Implications of Silent Failures

The costs associated with silent failures can be substantial. In multi-step processes, a single erroneous output can lead to multiple unnecessary API calls. For example, if a refund process loops due to a hallucinated output, it could generate numerous calls to the LLM, resulting in unexpected expenses. Ajah's circuit breaker feature mitigates this risk by limiting the number of calls made in a session, effectively preventing runaway loops and containing costs. This feature is particularly valuable in production environments where budget overruns can have serious implications. By implementing Ajah, organizations can enhance observability and achieve significant cost savings by minimizing unnecessary API usage.

### Addressing Security Concerns in AI Systems

As AI agents gain more autonomy, the potential for security vulnerabilities increases, particularly concerning prompt injection attacks. Ajah addresses this by scanning incoming prompts for suspicious patterns that could lead to security breaches. This proactive approach not only enhances the security posture of AI systems but also aligns with ethical considerations surrounding AI deployment. By ensuring that agents operate within defined parameters and do not inadvertently disclose sensitive information, developers can build trust in AI systems.

Improving observability in AI agents extends beyond technical enhancements; it has profound implications for user trust and system reliability.
