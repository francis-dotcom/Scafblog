When VoIPBin receives a call, it sends a POST request to your webhook. Your webhook returns a list of actions — speak, listen, transfer, hang up. VoIPBin executes them.
Create main.go:
package main

import (
    "encoding/json"
    "fmt"
    "log"
    "net/http"
)

// VoIPBin sends this when a call event occurs
type CallEvent struct {
    CallID    string `json:"call_id"`
    Type      string `json:"type"`
    Transcript string `json:"transcript,omitempty"`
}

// We return a list of actions
type Action struct {
    Type string `json:"type"`
    Text string `json:"text,omitempty"`
}

func webhookHandler(w http.ResponseWriter, r *http.Request) {
    var event CallEvent
    if err := json.NewDecoder(r.Body).Decode(&event); err != nil {
        http.Error(w, "bad request", http.StatusBadRequest)
        return
    }

    log.Printf("event: type=%s call_id=%s transcript=%q",
        event.Type, event.CallID, event.Transcript)

    var actions []Action

    switch event.Type {
    case "call.started":
        // Greet the caller
        actions = []Action{
            {Type: "talk", Text: "Hello! You have reached our AI assistant. How can I help you today?"},
            {Type: "listen"},
        }

    case "call.input":
        // Caller said something — respond based on transcript
        reply := getAIReply(event.Transcript)
        actions = []Action{
            {Type: "talk", Text: reply},
            {Type: "listen"},
        }

    default:
        // End anything we do not handle
        actions = []Action{
            {Type: "hangup"},
        }
    }

    w.Header().Set("Content-Type", "application/json")
    json.NewEncoder(w).Encode(actions)
}

func getAIReply(input string) string {
    // Plug in your LLM here — OpenAI, Anthropic, Gemini, local model
    // For this tutorial, we use a simple static response
    if input == "" {
        return "Sorry, I did not catch that. Could you repeat?"
    }
    return fmt.Sprintf("You said: %s. Let me look that up for you — our team will follow up shortly!", input)
}

func main() {
    http.HandleFunc("/webhook", webhookHandler)
    log.Println("Webhook listening on :8080")
    log.Fatal(http.ListenAndServe(":8080", nil))
}

import (
    "context"

func getAIReply(input string) string {
    client := openai.NewClient("OPENAI_API_KEY")

    resp, err := client.CreateChatCompletion(
        context.Background(),
        openai.ChatCompletionRequest{
            Model: openai.GPT4oMini,
            Messages: []openai.ChatCompletionMessage{
                {
                    Role:    openai.ChatMessageRoleSystem,
                    Content: "You are a friendly customer support agent. Keep responses under 30 words for voice.",
                },
                {
                    Role:    openai.ChatMessageRoleUser,
                    Content: input,
                },
            },
        },
    )
    if err != nil {
        return "I am having trouble right now. Please try again."
    }

    return resp.Choices[0].Message.Content
}

Two things to keep in mind for voice LLM responses:
Keep it short. Nobody wants to listen to a paragraph read aloud. Aim for 1-2 sentences.
Avoid markdown. TTS engines will literally say "asterisk asterisk bold asterisk asterisk". Write plain prose.

### The Underappreciated Role of Go in AI Voice Applications

Go, known for its efficiency and concurrency capabilities, is often overshadowed by languages like Python when it comes to developing AI voice applications. However, Go's performance characteristics and strong typing system make it an excellent choice for building scalable voice agents. By leveraging Go, developers can create applications that are not only efficient but also maintainable, without the need to switch to more commonly used languages in the AI space.

### VoIPBin: A Comprehensive SDK for Voice Infrastructure

VoIPBin provides a robust SDK that abstracts the complexities of voice communication, allowing Go developers to focus on application logic rather than the underlying VoIP protocols. This SDK simplifies the handling of SIP signaling, RTP media streaming, and the integration of speech-to-text (STT) and text-to-speech (TTS) functionalities. With VoIPBin, developers can build AI voice agents capable of real-time interactions without getting bogged down by the intricacies of telephony infrastructure.

### Implementing a Secure Webhook for Incoming Calls

The heart of your AI voice agent is a webhook that processes incoming call events. Below is an implementation that handles these events and generates appropriate actions. 

```go
package main

import (
    "encoding/json"
    "fmt"
    "log"
    "net/http"
    "sync"
)

type CallEvent struct {
    CallID    string `json:"call_id"`
    Type      string `json:"type"`
    Transcript string `json:"transcript,omitempty"`
}

type Action struct {
    Type string `json:"type"`
    Text string `json:"text,omitempty"`
}

var sessions sync.Map // To maintain conversation state

// Function to verify the authenticity of incoming requests
func verifyRequest(r *http.Request) bool {
    // This is a placeholder. Implement your authentication logic here.
    // For example, check for a valid API token or HMAC signature.
    return true
}

func webhookHandler(w http.ResponseWriter, r *http.Request) {
    if !verifyRequest(r) {
        http.Error(w, "Unauthorized", http.StatusUnauthorized)
        return
    }

    var event CallEvent
    if err := json.NewDecoder(r.Body).Decode(&event); err != nil {
        http.Error(w, "bad request", http.StatusBadRequest)
        return
    }

    log.Printf("event: type=%s call_id=%s transcript=%q", event.Type, event.CallID, event.Transcript)

    var actions []Action

    switch event.Type {
    case "call.started":
        actions = []Action{
            {Type: "talk", Text: "Hello! You have reached our AI assistant. How can I help you today?"},
            {Type: "listen"},
        }

    case "call.input":
        reply := getAIReply(event.Transcript)
        actions = []Action{
            {Type: "talk", Text: reply},
            {Type: "listen"},
        }
        storeConversationState(event.CallID, event.Transcript)

    default:
        actions = []Action{
            {Type: "hangup"},
        }
    }

    w.Header().Set("Content-Type", "application/json")
    json.NewEncoder(w).Encode(actions)
}

// Function to store the conversation state
func storeConversationState(callID, transcript string) {
    // Store the transcript in the session map
    sessions.Store(callID, transcript)
}

func main() {
    http.HandleFunc("/webhook", webhookHandler)
    log.Println("Webhook listening on :8080")
    log.Fatal(http.ListenAndServe(":8080", nil))
}
```

This code establishes a basic HTTP server that listens for incoming call events. The `webhookHandler` function decodes the incoming JSON payload, determines the appropriate actions based on the event type, and maintains the conversation state using a concurrent map. Additionally, the `verifyRequest` function is included to ensure that incoming requests are authenticated, which is crucial for securing your webhook.

### Integrating Speech-to-Text and Text-to-Speech

To enhance your voice agent's functionality, integrating STT and TTS is essential. VoIPBin simplifies these processes, allowing you to focus on the application logic. For TTS, you can specify the text to be spoken directly in the action returned by your webhook. The `Transcript` field in the `CallEvent` will contain the caller's speech converted to text, enabling your application to respond intelligently based on user input.

### Best Practices for Deployment and Scaling

When deploying your AI voice agent, consider the following best practices to ensure scalability and reliability:

1. **Webhook Authentication**: Implement HMAC signatures or token-based verification to ensure that incoming requests are from trusted sources.

2. **State Management**: Use concurrent data structures like `sync.Map` to maintain conversation state across calls, keyed by `call_id`.

3. **Graceful Shutdown**: Implement graceful shutdowns for your HTTP server to avoid dropping calls during deployment.

4. **Performance Monitoring**: Use logging and monitoring tools to track performance metrics and identify bottlenecks in real-time.

5. **Load Testing**: Conduct load testing to understand how your application behaves under stress and ensure it can handle multiple concurrent calls efficiently.
