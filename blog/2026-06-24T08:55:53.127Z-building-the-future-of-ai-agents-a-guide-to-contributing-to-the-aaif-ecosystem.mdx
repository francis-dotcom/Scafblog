Model Context Protocol (MCP) is the foundational layer. It standardizes how AI agents connect to tools, data sources, and services. Think of it as a universal adapter between any agent and any tool.
MCP servers expose three core primitives:
Tools: Functions the agent can call (e.g., search_code, execute_query)
Resources: Data the agent can read (e.g., files, database schemas)
Prompts: Reusable templates for common agent tasks
The protocol uses JSON-RPC 2.0 over multiple transports (stdio, SSE, Streamable HTTP). Build an MCP server once, and any MCP-compatible agent can use it. No more rebuilding integrations per framework.
The current spec version uses date-based versioning (2025-11-25) and includes OAuth authentication, progress notifications, logging, and sampling (servers requesting LLM completions through the client).
The ecosystem is large. Official SDKs exist in 10 languages: TypeScript, Python, Go, Rust, Java, Kotlin, Swift, C#, PHP, and Ruby. There are 7 reference servers (filesystem, git, memory, fetch, sequential thinking, time, everything) and an MCP Inspector for testing and debugging.

Goose is where MCP comes to life. It's an open source AI agent built in Rust with a native desktop app (macOS, Linux, Windows), a CLI, and an API server.
Goose isn't just a coding agent. You can use it for research, writing, automation, and data analysis. It connects to 70+ MCP extensions and supports 15+ LLM providers (Anthropic, OpenAI, Google, Ollama, OpenRouter, Azure, Bedrock, and more). You can also use existing Claude, ChatGPT, or Gemini subscriptions via ACP (Agent Client Protocol).
The Rust workspace is organized into focused crates:
crates/
├── goose              # core agent logic
├── goose-cli          # CLI entry point
├── goose-server       # backend (binary: goosed)
├── goose-mcp          # MCP extension integrations
├── goose-acp-macros   # ACP proc macros
└── goose-test         # test utilities
ui/desktop/            # Electron desktop app

Development uses Hermit for reproducible tooling and just for task automation.

AGENTS.md solves a specific problem: README files aren't written for AI agents. They tell humans what a project does, but they don't give an agent the build commands, test patterns, and conventions it needs to actually work on the codebase.
An AGENTS.md file is a dedicated, predictable place for agent-specific context:
## Dev environment tips
- Use `pnpm dlx turbo run where <project_name>` to jump to a package.
- Check the name field inside each package's package.json to confirm the right name.

## Testing instructions
- Run `pnpm turbo run test --filter <project_name>`.
- Add or update tests for the code you change, even if nobody asked.

## PR instructions
- Title format: [<project_name>] <Title>
- Always run `pnpm lint` and `pnpm test` before committing.

No spec, no protocol. Just a convention. The repository includes a Next.js website at agents.md with examples and a community showcase.
Notably, several AAIF projects already use AGENTS.md files themselves. Goose's CLAUDE.md points to its own AGENTS.md. The MCP spec repo, MCP Inspector, and MCP Go SDK all have AGENTS.md files guiding contributors and agents alike.

AgentGateway is a Rust-based proxy that sits between your agents, LLMs, tools, and other agents. It provides drop-in security, observability, and governance for agentic traffic.
It handles three types of communication:
LLM Gateway: Routes to LLM providers (OpenAI, Anthropic, Gemini, Bedrock, etc.) through a unified OpenAI-compatible API with budget controls, prompt enrichment, load balancing, and failover.
MCP Gateway: Connects agents to tools via MCP with tool federation, multi-transport support, OpenAPI integration, and OAuth authentication.
A2A Gateway: Enables agent-to-agent communication using Google's A2A protocol with capability discovery and task collaboration.
Production features include:
Auth: JWT, API keys, OAuth, fine-grained RBAC with CEL policy engine
Guardrails: regex filtering, OpenAI moderation, AWS Bedrock Guardrails, Google Model Armor, custom webhooks
Observability: OpenTelemetry metrics, logs, and distributed tracing
Inference routing: Kubernetes Inference Gateway extensions with GPU utilization, KV cache, and LoRA adapter awareness
From the project charter:
The mission is to create a secure, scalable, and standardized foundation for AI agents to discover, communicate with, and leverage external tools and services.

### The Foundation of Agentic AI Infrastructure

The Agentic AI Foundation (AAIF) is pioneering the development of a comprehensive infrastructure for AI agents, facilitating their evolution from simple chat interfaces to complex systems capable of interacting with various tools, databases, and other agents. This transition necessitates a robust framework that allows developers to create and integrate AI agents efficiently. Understanding the foundational projects of the AAIF is crucial for developers who wish to contribute to this transformative ecosystem.

### Exploring the Core Projects of AAIF

At the heart of the AAIF's mission are four core projects: the Model Context Protocol (MCP), Goose, AGENTS.md, and AgentGateway. Each project plays a vital role in establishing a cohesive environment for AI agents, promoting interoperability, documentation standards, and secure communications.

### The Model Context Protocol (MCP): A Universal Adapter

The Model Context Protocol (MCP) is the cornerstone of the AAIF infrastructure, designed to standardize how AI agents connect with tools, data sources, and services. The MCP operates as a universal adapter, simplifying integration across diverse systems. It exposes three fundamental primitives: tools, resources, and prompts.

- **Tools** are functions that agents can invoke, such as executing queries or performing calculations. For instance, an agent could utilize a tool to fetch real-time weather data from an external API.

- **Resources** refer to the data that agents can access, which may include files, databases, or APIs. A typical resource might be a JSON file containing user preferences or historical data.

- **Prompts** serve as reusable templates for common tasks, enhancing efficiency in agent operations. For example, a prompt could be a predefined query structure that agents use to retrieve information from a knowledge base.

The MCP leverages JSON-RPC 2.0 over various transport methods, including standard input/output, Server-Sent Events (SSE), and streamable HTTP. This versatility enables developers to create MCP servers that any compatible agent can utilize, significantly reducing the complexity of building integrations across different frameworks. This standardization is crucial for developers aiming to ensure their agents can interact seamlessly with other systems.

### Goose: Implementing MCP in an Open-Source Framework

Goose is an open-source AI agent framework that embodies the principles of the MCP, built in Rust. It is designed for a wide range of functionalities, including research, automation, and data analysis. Goose connects to over 70 MCP extensions and supports more than 15 large language model (LLM) providers, such as OpenAI's GPT and Anthropic's Claude.

The architecture of Goose is modular, with distinct components organized into crates that handle core logic, command-line interfaces (CLI), and API servers. For example, developers can easily integrate new functionalities by leveraging existing subscriptions to LLMs through the Agent Client Protocol (ACP). This modularity enhances extensibility and empowers developers to build sophisticated AI applications tailored to specific use cases. A practical example of Goose in action could involve automating data analysis workflows, where agents pull data from various sources, process it, and generate insightful reports.

### AGENTS.md: Standardizing Documentation for AI Agents

While the MCP and Goose provide the technical foundation for AI agents, AGENTS.md addresses a critical need for effective documentation and conventions. Traditional README files often lack the necessary context for AI agents to navigate codebases effectively. AGENTS.md files serve as dedicated resources that provide agent-specific context, including development environment tips, testing instructions, and pull request guidelines.

By standardizing this documentation format, AGENTS.md enables agents to autonomously understand and interact with codebases, thereby improving their effectiveness and reducing the cognitive load on developers. This is particularly beneficial in collaborative environments where multiple contributors may be working on the same project, ensuring that everyone is aligned on expectations and practices. For example, an AGENTS.md file might include a section on common pitfalls when setting up the development environment, along with troubleshooting steps.

### AgentGateway: Ensuring Secure Communication Among Agents

AgentGateway complements the AAIF ecosystem by providing a secure and scalable proxy for agent communications. Built in Rust, this gateway facilitates interactions between agents, LLMs, and tools, ensuring that data flows securely and efficiently. AgentGateway supports multiple communication types, including LLM routing, MCP connections, and agent-to-agent (A2A) interactions.

A standout feature of AgentGateway is its robust security framework, which includes support for JSON Web Tokens (JWT), OAuth authentication, and fine-grained role-based access control (RBAC). This level of security is essential for production environments where sensitive data may be processed, ensuring that only authorized agents can access specific functionalities and data. For instance, an agent might require different access levels when interacting with personal user data compared to public datasets. The implementation of such security measures ensures that developers can build applications with confidence in their data protection protocols.

### Contribution Pathways: How to Get Involved

The AAIF actively encourages contributions from developers of all skill levels, providing clear pathways for involvement across its core projects. Each project has its own set of guidelines and entry points, making it easier for newcomers to find suitable starting points.

#### Getting Started with AGENTS.md

AGENTS.md is the most accessible project for new contributors. Developers familiar with TypeScript and React can quickly get involved by enhancing documentation, adding examples, or improving the website's design. For instance, contributors can add real-world examples of AGENTS.md files from existing projects, which can serve as valuable references for others.

#### Contributing to the Model Context Protocol

The Model Context Protocol presents a moderate challenge, requiring a solid understanding of Node.js and TypeScript. Contributors can enhance documentation, propose schema examples, or contribute to the development of SDKs in various programming languages. The MCP Inspector tool provides a hands-on way to learn about the protocol interactively, allowing contributors to test and debug MCP servers before diving into more complex contributions.

#### Engaging with the Goose Framework

Contributing to Goose requires proficiency in Rust and familiarity with its ecosystem. New contributors can start by addressing small bugs or improving existing features. The project's clear contributing guidelines and supportive community facilitate navigating the initial learning curve. For example, contributors might focus on integrating new LLM extensions or enhancing the command-line interface.

#### Diving into AgentGateway

AgentGateway is the most demanding project, necessitating a deep understanding of networking, security, and proxy architecture. However, even here, contributors can make meaningful contributions by addressing bugs, improving documentation, or adding new features. For instance, contributors could work on enhancing the observability features or integrating new guardrail providers to improve security.

### Community Support: Fostering Collaboration

The AAIF ecosystem is bolstered by a vibrant community of developers and enthusiasts. Each project has dedicated communication channels, such as Discord servers and GitHub Discussions, where contributors can seek assistance, share ideas, and collaborate on solutions. This sense of community is crucial for fostering a collaborative environment where developers can learn from one another and grow their skills.

### The Importance of Collaborative Development in AI

As the AI landscape continues to evolve, the importance of collaborative efforts becomes increasingly clear. The AAIF's infrastructure projects—MCP, Goose, AGENTS.md, and AgentGateway—represent a concerted effort to create a unified foundation for AI agents. By contributing to these projects, developers not only enhance their own skills but also play a vital role in shaping the future of AI technology.

### Conclusion: Building the Future of AI Agents Together

The Agentic AI Foundation offers a unique opportunity for developers to engage with cutting-edge technology and contribute to the development of a cohesive AI ecosystem. By understanding the foundational projects and actively participating in their evolution, developers can help build the infrastructure that will support the next generation of AI agents. Whether you are a seasoned engineer or a newcomer to the field, there is a place for you in this collaborative effort. Join us in building the future of AI agents!
