Tidak perlu langsung 20 tool. Mulai dari yang paling sering ditanyakan — prinsip yang sama dengan MVP.
import { McpServer } from "@modelcontextprotocol/sdk/server/mcp.js";
import { StdioServerTransport } from "@modelcontextprotocol/sdk/server/stdio.js";
import { z } from "zod";

const server = new McpServer({
  name: "konveksi-ops",
  version: "1.0.0",
});

server.tool(
  "check_material_stock",
  "Cek stok bahan kain berdasarkan jenis material",
  { material: z.string().describe("Jenis kain, mis. 'drill', 'oxford', 'kain ESD'") },
  async ({ material }) => {
    const stock = await queryInventory(material); // koneksi ke DB/Sheets
    return {
      content: [{
        type: "text",
        text: JSON.stringify(stock), // { material, meter_tersedia, lokasi_rak, updated_at }
      }],
    };
  }
);

const transport = new StdioServerTransport();
await server.connect(transport);

### The Fragmentation of Data in Manufacturing

Manufacturing enterprises are increasingly challenged by the fragmentation of data across multiple systems and platforms. Legacy systems, spreadsheets, and disparate applications create silos that obstruct real-time access to critical information. For example, a sales team may rely on outdated Excel sheets for pricing, while inventory data is maintained in a separate Google Sheet. This disconnection leads to inefficiencies, delayed responses, and ultimately, a loss of competitive advantage. The need for a cohesive data integration strategy has never been more pressing.

### The Role of Model Context Protocol (MCP)

The Model Context Protocol (MCP) offers a robust framework for addressing these integration challenges. MCP is an open standard designed to facilitate seamless communication between AI systems and operational data sources. By establishing a unified protocol for data access, MCP empowers AI agents to retrieve real-time information, transitioning them from passive responders to proactive decision-makers. This architecture not only simplifies data access but also enhances the effectiveness of AI applications in manufacturing environments, allowing for quicker and more informed decision-making.

### Conducting a Comprehensive Data Audit

The first step in implementing an MCP server is to conduct a thorough audit of existing data sources. This involves identifying where critical operational metrics—such as pricing, inventory levels, and production statuses—are stored. For instance, a manufacturing firm may discover that pricing data resides in an Excel spreadsheet while inventory information is tracked in a Google Sheet. Understanding the landscape of these data silos is crucial for designing an effective integration strategy that does not require complete data migration, thus preserving existing workflows.

### Defining Tool Contracts for Clarity

Once the data sources are identified, the next step is to define tool contracts using Zod or JSON Schema. Tool contracts specify the input and output requirements for each data access tool, ensuring clear communication between AI agents and the MCP server. For example, a tool contract for checking material stock might require parameters such as material type and quantity. Here’s a more detailed example of a tool contract:

```javascript
const checkMaterialStockContract = z.object({
  material: z.string().describe("Type of material, e.g., 'drill', 'oxford'"),
  quantity: z.number().describe("Required quantity of the material"),
});
```

This clarity allows AI agents to accurately select the appropriate tools based on user queries, enhancing their responsiveness and reliability.

### Implementing the MCP Server: A Practical Guide

With tool contracts established, the next phase is to implement the MCP server and connect it to the identified data sources. Below is a code snippet demonstrating a basic implementation of an MCP server that connects to a Google Sheet for inventory checks:

```javascript
import { McpServer } from "@modelcontextprotocol/sdk/server/mcp.js";
import { StdioServerTransport } from "@modelcontextprotocol/sdk/server/stdio.js";
import { z } from "zod";

const server = new McpServer({
  name: "manufacturing-ops",
  version: "1.0.0",
});

server.tool(
  "check_material_stock",
  "Check material stock based on type and quantity",
  checkMaterialStockContract,
  async ({ material, quantity }) => {
    const stock = await queryInventory(material); // Connect to Sheets or DB
    return {
      content: [{
        type: "text",
        text: JSON.stringify(stock), // { material, available_meters, rack_location, updated_at }
      }],
    };
  }
);

const transport = new StdioServerTransport();
await server.connect(transport);
```

This implementation allows real-time queries about material stock, enabling AI agents to provide accurate and timely information.

### Ensuring Security and Input Validation

As part of the implementation, it is critical to validate all inputs to prevent security vulnerabilities such as tool poisoning and prompt injection. Input validation checks should ensure that only expected material types are processed. Additionally, implementing secure access controls is vital, especially for tools that modify data. For example, only authenticated users should have permission to execute write operations, thereby protecting sensitive data from unauthorized access.

### Connecting AI Agents to the MCP Server

After the MCP server is operational, the next step is to connect AI agents to the server and configure appropriate permissions. This setup allows AI agents, such as ChatGPT or Claude, to access real-time data. It is advisable to implement a human-in-the-loop approval system for any tools that modify data, ensuring that sensitive operations are validated by human operators. This approach not only enhances security but also builds trust within the operational team.

### Monitoring Performance and Iterative Improvements

The final step in the implementation process is to monitor the performance of the MCP server and AI agents. Gathering operational feedback is crucial for iterative improvements. For instance, if users frequently request information that is not currently available through existing tools, it may indicate the need for additional tools or enhancements. Regular monitoring will help identify bottlenecks and opportunities for optimization, ensuring that the system evolves in line with user needs.

### Real-World Case Study: CV. Mitra Mandiri Design

To illustrate the practical application of MCP in manufacturing, consider the case of CV. Mitra Mandiri Design, a producer of industrial uniforms based in Karawang. The company faced challenges in providing timely updates on pricing and stock levels to its sales team. By implementing an MCP server, they were able to create tools that provided real-time access to critical data.

The initial implementation focused on three key tools:

| Tool Name             | Functionality                          | Data Source                  | Update Frequency |
|-----------------------|----------------------------------------|------------------------------|------------------|
| get_price_estimate    | Estimate price per item + quantity     | Pricing Table                | Weekly           |
| check_material_stock   | Check remaining stock of materials     | Warehouse Inventory Sheet    | Daily            |
| get_production_status  | Current status of production orders     | Internal Production Log      | Real-time        |

This approach allowed the sales team to respond to customer inquiries with accurate information, significantly reducing the time required to provide estimates and updates.

### Addressing Security Concerns in AI Integration

When integrating AI agents with operational data, security must be a top priority. The threat landscape includes risks such as malicious server attacks, data poisoning, and privilege escalation. Implementing robust security measures—such as input validation, access controls, and audit trails—can mitigate these risks. Each tool invocation should be logged, capturing details such as who accessed the data, when, and what parameters were used. This practice not only aids in debugging but also ensures compliance with data governance policies.

The journey from fragmented data silos to integrated, responsive systems is not just a technical upgrade; it represents a strategic shift that can provide a competitive advantage in an increasingly data-driven world. Embracing these changes will position manufacturing businesses at the forefront of operational excellence, driving future innovations and efficiencies.
