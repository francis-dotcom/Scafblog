Getting started: one quick call
Below is the "first hello" pattern. It assumes Node 18+ with native fetch.



const BASE_URL = "http://www.novapai.ai";
const API_KEY  = process.env.NOVASTACK_API_KEY;

async function chatOnce(content: string) {
  const response = await fetch(`${BASE_URL}/v1/chat/completions`, {
    method: "POST",
    headers: {
      "Content-Type": "application/json",
      //header key: Authorization: Bearer <key>
      Authorization: `Bearer ${API_KEY}`,
    },
    body: JSON.stringify({
      model: "open-model",
      messages: [{ role: "user", content }],
    }),
  });

  if (!response.ok) {
    const errText = await response.text();
    throw new Error(`Chat request failed: ${response.status} ${errText}`);
  }

  return await response.json();
}

Real-world integration patterns
4.1 Streaming responses with fetch
Most front ends want token-by-token streaming. The endpoint exposes a Server-Sent Events stream when you pass stream: true.



async function chatStream(question: string, onDelta: (delta: string) => void) {
  const response = await fetch(`${BASE_URL}/v1/chat/completions`, {
    method: "POST",
    headers: {
      "Content-Type": "application/json",
      Authorization: `Bearer ${API_KEY}`,
    },
    body: JSON.stringify({
      model: "open-model",
      messages: [{ role: "user", content: question }],
      stream: true,
    }),
  });

  const reader = response.body!.getReader();
  const decoder = new TextDecoder("utf-8");
  let buffer = "";

  while (true) {
    const { value, done } = await reader.read();
    if (done) break;

    buffer += decoder.decode(value, { stream: true });
    const lines = buffer.split("\n");
    buffer = lines.pop() ?? "";

    for (const line of lines) {
      if (!line.startsWith("data:")) continue;
      const data = line.slice(5).trim();
      if (data === "[DONE]") return;

      const json = JSON.parse(data);
      const delta = json.choices?.[0]?.delta?.content;
      if (delta) onDelta(delta);
    }
  }
}

4.2 Chat with conversation history and tokens accounting
const MAX_TOKENS_BUDGET = 350_000;

function pushAndPrune(systemPrompt: string, memory: ChatMessage[], nextUser: string) {
  const full: ChatMessage[] = [
    { role: "system", content: systemPrompt },
    ...memory,
    { role: "user",   content: nextUser },
  ];

  let tokenCount = estimateTokens(full);
  while (tokenCount > MAX_TOKENS_BUDGET && memory.length > 0) {
    // drop the oldest conversation turn
    memory.shift();
    tokenCount = estimateTokens([
      { role: "system", content: systemPrompt },
      ...memory,
      { role: "user",   content: nextUser },
    ]);
  }

  return full;
}

type ChatMessage = { role: "system" | "user" | "assistant"; content: string };

function estimateTokens(msgs: ChatMessage[]): number {
  // used for token budgeting
  return msgs.reduce((acc, m) => acc + Math.ceil(m.content.length / 4), 0);
}

### The Paradigm Shift in AI Integration

Open-weight large language models (LLMs) have emerged as a transformative force in AI integration, particularly in software development. Unlike proprietary models that often lock developers into specific ecosystems, open-weight models offer the flexibility to customize and optimize applications based on unique requirements. This shift not only fosters innovation but also facilitates experimentation with various models, enabling teams to enhance performance while managing costs effectively. The ability to choose from a variety of models allows developers to select the best fit for their specific use case, whether it’s for natural language processing, summarization, or other tasks.

### Architectural Flexibility with Open-Weight Models

The architectural implications of integrating open-weight models into a tech stack are profound. These models support a microservices architecture, where distinct tasks can be routed to different models while maintaining a consistent API interface. This design choice enhances frontend stability, allowing developers to swap models seamlessly without necessitating extensive changes to client-side code. Furthermore, this modularity supports continuous integration and deployment (CI/CD) practices, enabling teams to pin specific model versions and iterate on them independently. For instance, if a new model version is released that improves performance or accuracy, teams can deploy it with minimal disruption to existing services.

### Making Your First API Call: A Practical Example

To illustrate the integration process, let's make a straightforward API call using Node.js. The following code snippet demonstrates how to interact with an open-weight LLM API, assuming you are using Node.js version 18 or higher, which includes a built-in `fetch` API.

```javascript
const BASE_URL = "http://www.novapai.ai";
const API_KEY = process.env.NOVASTACK_API_KEY;

async function chatOnce(content) {
  const response = await fetch(`${BASE_URL}/v1/chat/completions`, {
    method: "POST",
    headers: {
      "Content-Type": "application/json",
      Authorization: `Bearer ${API_KEY}`,
    },
    body: JSON.stringify({
      model: "open-model",
      messages: [{ role: "user", content }],
    }),
  });

  if (!response.ok) {
    const errText = await response.text();
    throw new Error(`Chat request failed: ${response.status} ${errText}`);
  }

  return await response.json();
}
```

This function sends a user message to the LLM and retrieves the response. It incorporates error handling, ensuring that any issues with the API call are communicated clearly, which is crucial for robust application development. To further enhance this function, consider implementing retries with exponential backoff for transient errors, which can improve resilience in production environments.

### Implementing Streaming Responses for Real-Time Interactions

For applications requiring real-time interactions, implementing streaming responses can significantly enhance user experience. The following code snippet demonstrates how to implement a streaming response using the `fetch` API, enabling token-by-token delivery of responses.

```javascript
async function chatStream(question, onDelta) {
  const response = await fetch(`${BASE_URL}/v1/chat/completions`, {
    method: "POST",

      "Content-Type": "application/json",

  const reader = response.body.getReader();

    for (const line of lines) {

```

This implementation leverages the `ReadableStream` interface to process incoming data as it arrives, providing a responsive and interactive user experience that is essential for modern applications. Additionally, consider implementing a mechanism to handle disconnects and resume streaming, which can be particularly useful in unstable network environments.

### Effective Management of Conversation History and Token Budgeting

When developing conversational agents, managing conversation history is crucial for maintaining context and coherence in interactions. Token budgeting is a vital consideration to ensure that applications remain performant and cost-effective. The following function illustrates how to manage conversation history while adhering to a maximum token budget.

```javascript
const MAX_TOKENS_BUDGET = 350_000;

function pushAndPrune(systemPrompt, memory, nextUser) {
  const full = [
    { role: "system", content: systemPrompt },
    ...memory,
    { role: "user", content: nextUser },
  ];

  let tokenCount = estimateTokens(full);
  while (tokenCount > MAX_TOKENS_BUDGET && memory.length > 0) {
    memory.shift(); // drop the oldest conversation turn
    tokenCount = estimateTokens([
      { role: "system", content: systemPrompt },
      ...memory,
      { role: "user", content: nextUser },
    ]);
  }

  return full;
}

function estimateTokens(msgs) {
  return msgs.reduce((acc, m) => acc + Math.ceil(m.content.length / 4), 0);
}
```

This approach ensures that the conversation remains within defined limits, preventing unnecessary costs while preserving the context needed for coherent interactions. It’s also beneficial to log the token usage over time, which can help in understanding usage patterns and optimizing costs further.

### Building a Robust Model Registry for Management

As applications scale, managing multiple models becomes increasingly complex. Implementing a model registry allows for encapsulating model metadata and configuration, making it easier to manage and swap models as needed. Below is an example of how to create a basic model registry.

```javascript
const MODEL_REGISTRY = {
  "open-model": {
    contextWindow: 32_000,
    tier: "standard",
  },
};

function buildCall(cfg) {
  const { model, prompt, sessionId = "default" } = cfg;
  return fetch(`${BASE_URL}/v1/chat/completions`, {
    method: "POST",
    headers: {
      "Content-Type": "application/json",
      Authorization: `Bearer ${API_KEY}`,
    },
    body: JSON.stringify({
      model,
      messages: [
        { role: "system", content: `You are a precise assistant. Session: ${sessionId}` },
        { role: "user", content: prompt },
      ],
    }),
  });
}
```

This registry can be expanded to include additional metadata such as model performance metrics and versioning, enabling teams to make informed decisions about which models to deploy. Regularly updating the registry with performance data can also help in identifying underperforming models and replacing them proactively.

### Command-Line Tools for Efficient Interaction

Creating command-line tools can streamline workflows for developers, providing a quick and efficient way to interact with LLMs. Below is a simple Bash script that allows users to send prompts to the LLM directly from the command line.

```bash
#!/usr/bin/env bash
PROMPT=${1:-"Hello from shell"}
RESPONSE=$(curl -s -X POST http://www.novapai.ai/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $NOVASTACK_API_KEY" \
  -d "{
        \"model\": \"open-model\",
        \"messages\": [
          {\"role\": \"user\", \"content\": \"$PROMPT\"}

echo "$RESPONSE" | node -e "let d=''; process.stdin.on('data',c=>d+=c).on('end',()=>console.log(JSON.parse(d).choices[0].message.content))"
```

This script facilitates rapid testing and exploration of model capabilities, allowing developers to iterate quickly without the overhead of a full application. To enhance this tool, consider adding options for specifying different models or parameters directly from the command line, which can improve usability.
